## 一、项目概述

mimgs 是一个企业级 C++ 图像处理模块，对外提供统一的 Pipeline 式 API，支持将多个图像处理操作（缩放、旋转、拼图等）编排为有序流水线，并通过 LRU 缓存机制自动复用中间计算结果，从而在重复请求场景下显著提升吞吐量。

**核心能力一览**：

| 能力 | 说明 |
|------|------|
| **Pipeline 编排** | 将 N 个算子按顺序串联，上一步的输出自动成为下一步的输入 |
| **算子可扩展** | 新增算子仅需实现 `IOperator` 接口并注册，无需修改任何已有代码（开闭原则） |
| **LRU 缓存** | 全局单例缓存，每个算子步骤执行前先查缓存，命中则跳过计算 |
| **线程安全** | 每次请求创建独立的 `IContext` 实例（栈上局部变量），天然无数据竞争 |
| **编译隔离** | Pimpl 模式 + 符号隐藏，外部用户只需 `#include "mimgs/Mimgs.hpp"` 一个头文件 |
| **ABI 稳定性** | 纯虚接口 `IImages` 作为契约，动态库升级不破坏二进制兼容性 |

### 2.2 核心设计原则

| # | 原则 | 实现手段 |
|---|------|---------|
| 1 | **编译隔离** | Pimpl (Pointer to Implementation) 模式，外部头文件仅暴露 `class Impl` 前置声明，内部依赖（OpenCV、STL 容器等）完全隐藏 |
| 2 | **ABI 稳定性** | 纯虚接口 `IImages` 作为契约，门面类通过 `unique_ptr<Impl>` 持有实现；动态库升级不影响外部二进制 |
| 3 | **符号隐藏** | CMake 全局设置 `CMAKE_CXX_VISIBILITY_PRESET hidden`，仅 `MIMGS_API` 宏标记的符号导出到动态符号表 |
| 4 | **开闭原则** | 新增算子仅需实现 `IOperator` 接口并调用 `RegisterOperator`，无需修改任何已有代码 |
| 5 | **线程安全** | `IContext` 作为每次请求的栈上局部变量，天然无共享状态；全局单例组件（Registry、Cache）使用互斥锁保护 |
| 6 | **零拷贝传递** | `ImageAsset` 禁用拷贝构造（`= delete`），通过 `shared_ptr` 在 Context 中流转，避免意外深拷贝巨量像素数据 |
| 7 | **单一职责** | 每个算子只负责一种图像变换，公共逻辑（格式转换、内存拷贝）抽到 Utils 工具函数 |

### 3.2 像素格式枚举 — PixelFormat

**完整源码**：

```cpp
// source/mimgs/common/Common.hpp (第 21-25 行)

enum class PixelFormat
{
    RGBA8888,   // 4 通道，每通道 8 bit，含 Alpha 透明度通道
    RGB888      // 3 通道，每通道 8 bit，不含 Alpha 透明度通道
};
```

**设计要点**：

- 使用 `enum class`（强类型枚举），防止与整型隐式转换，必须显式写 `PixelFormat::RGBA8888`
- 当前仅支持 8-bit 无符号整型像素格式，后续可扩展 `RGB161616`、`GRAY8`、`BGRA8888` 等
- 通道数通过工具函数 `GetChannelCount()` 获取，避免在业务代码中硬编码 `3` 或 `4`

**格式对照表**：

| 枚举值 | 通道数 | 每像素字节 | OpenCV 类型 | 典型用途 |
|--------|--------|-----------|-------------|---------|
| `RGBA8888` | 4 | 4 | `CV_8UC4` | 含透明度的 UI 素材、Logo |
| `RGB888` | 3 | 3 | `CV_8UC3` | 普通照片、无透明度图像 |

### 3.3 图像资源 — ImageAsset

**完整源码**：

```cpp
// source/mimgs/common/Common.hpp (第 28-47 行)

// 内部图像基础资源
struct ImageAsset
{
    std::string id;                           // 全局唯一标识（作为 Context 中的查找 key）
    uint32_t width{0};                        // 图像宽度（像素）
    uint32_t height{0};                       // 图像高度（像素）
    PixelFormat format{PixelFormat::RGBA8888};// 像素格式（默认 RGBA）
    std::unique_ptr<uint8_t[]> data{nullptr}; // 裸像素数据（堆分配，独占所有权）

    // 构造函数：构造时一次性分配所需内存
    ImageAsset(std::string_view asset_id, uint32_t w, uint32_t h, PixelFormat fmt)
        : id(asset_id), width(w), height(h), format(fmt)
    {
        size_t size = static_cast<size_t>(w) * h * (fmt == PixelFormat::RGBA8888 ? 4 : 3);
        data = std::make_unique<uint8_t[]>(size);
    }

    // 禁用拷贝 —— 防止意外深拷贝巨量像素数据
    ImageAsset(const ImageAsset &) = delete;
    ImageAsset &operator=(const ImageAsset &) = delete;

    // 允许移动 —— 支持零拷贝所有权转移
    ImageAsset(ImageAsset &&) noexcept = default;
    ImageAsset &operator=(ImageAsset &&) noexcept = default;
};
```

**逐行设计解读**：

| 成员 | 类型 | 说明 |
|------|------|------|
| `id` | `std::string` | 全局唯一标识符。作为 `IContext` 的 key，也是缓存签名的组成部分 |
| `width` / `height` | `uint32_t` | 使用无符号 32 位整数，避免负数尺寸；最大支持 4294967295 像素 |
| `format` | `PixelFormat` | 默认 `RGBA8888`，保证新构造的资产默认带 Alpha 通道 |
| `data` | `unique_ptr<uint8_t[]>` | 独占所有权的堆内存。析构时自动 `delete[]`，杜绝内存泄漏 |

**内存管理策略**：

```text
构造时分配:
  size = width * height * channels
  data = make_unique<uint8_t[]>(size)    ← 一次性分配连续内存

运行时使用:
  cv::Mat mat(h, w, type, data.get())    ← 零拷贝包装，共享同一片内存

传输时共享:
  shared_ptr<ImageAsset>                 ← 多个算子/缓存可共享同一资产

销毁时释放:
  ~ImageAsset()                          ← unique_ptr 自动 delete[]
```

**禁用拷贝、允许移动的设计意图**：

```text
❌ 拷贝构造 = delete     → 防止有人写出 ImageAsset b = a; 导致意外拷贝数 MB 像素数据
❌ 拷贝赋值 = delete     → 防止 asset1 = asset2; 导致双重释放或内存泄漏
✅ 移动构造 = default    → 允许 ImageAsset b = std::move(a); 零拷贝转移
✅ 移动赋值 = default    → 允许 asset1 = std::move(asset2); 零拷贝转移
```

### 3.4 算子参数基类 — OperatorParams

**完整源码**：

```cpp
// source/mimgs/common/Common.hpp (第 50-61 行)

// 所有算子参数的基类
struct OperatorParams
{
    std::string outputKey;  // 输出资产写入 Context 时使用的 key

    virtual ~OperatorParams() = default;  // 虚析构，确保子类正确析构

    virtual void Validate() const         // 参数校验（子类应 override 并先调用基类）
    {
        if (outputKey.empty())
            throw ProcessingException("output_key is empty");
    }

    virtual std::string GetCacheSignature() const = 0;  // 纯虚：缓存签名（子类必须实现）
};
```

**继承体系**：

```text
           OperatorParams (基类)
          /      |       |        \
    ScaleParams  RotateParams  PuzzleParams  PipelineParams
    ├──inputKey  ├──inputKey    ├──inputKeys[]  ├──inputKey[]
    ├──tarWidth  ├──angle       ├──rows         └──steps[]
    └──tarHeight                ├──cols
                                ├──cellWidth
                                ├──cellHeight
                                ├──padding
                                └──bgColor[4]
```

**Validate 链式校验模式**：

```text
子类 Validate()
    │
    ├── 1. 调用 OperatorParams::Validate()  → 校验 outputKey 非空
    │
    └── 2. 追加自身特有的校验逻辑           → 校验 inputKey / 尺寸 / 角度等
```

**GetCacheSignature 的设计意图**：

每个算子必须提供一个唯一的字符串签名，该签名由所有影响计算结果的参数组合而成。相同的签名意味着"输入相同 + 参数相同 = 结果相同"，可以安全地命中缓存。

### 3.5 内部共享上下文 — IContext（黑板模式）

**完整源码**：

```cpp
// source/mimgs/common/Common.hpp (第 64-86 行)

// 内部共享上下文
class IContext
{
private:
    std::unordered_map<std::string, std::shared_ptr<ImageAsset>> _assets;

public:
    void setAsset(std::shared_ptr<ImageAsset> asset)
    {
        if (!asset || asset->id.empty())
        {
            throw ProcessingException("Null or invalid asset.");
        }
        _assets[asset->id] = std::move(asset);
    }

    std::shared_ptr<ImageAsset> getAsset(const std::string &id) const
    {
        auto it = _assets.find(id);
        if (it != _assets.end())
            return it->second;
        return nullptr;
    }
};
```

**黑板模式（Blackboard Pattern）工作原理**：

```text
                  IContext（黑板容器）
                 ┌────────────────────────┐
                 │ "img_a"      → Asset   │
                 │ "img_b"      → Asset   │
                 │ "img_a_scaled" → Asset │
                 │ "img_b_rotated" → Asset│
                 │ "final"      → Asset   │
                 └────────────────────────┘
                        ▲        ▲
            读取(inputKey)│        │写入(outputKey)
                        │        │
          ┌─────────────┘        └─────────────┐
          │                                    │
    ┌─────┴─────┐  ┌─────┴─────┐  ┌─────┴─────┐
    │  Scale    │  │  Rotate   │  │  Puzzle   │
    │  Operator │  │  Operator │  │  Operator │
    └───────────┘  └───────────┘  └───────────┘
```

**核心设计要点**：

| 要点 | 说明 |
|------|------|
| **请求隔离** | 每次 `Images::execute()` 调用在栈上创建独立的 `IContext` 实例，不同请求之间不存在任何共享状态 |
| **线程安全** | 由于 Context 是栈上局部变量，不同线程的不同请求各自持有独立 Context，天然无数据竞争 |
| **算子间通信** | 算子之间不直接传递数据，而是通过 Context 的 key-value 进行间接通信（解耦） |
| **O(1) 查找** | 底层使用 `unordered_map`，通过 key 查找资产的时间复杂度为 O(1) |
| **shared_ptr 共享** | 同一个 Asset 可以被多个算子同时引用（如拼图算子引用多个前置步骤的输出），引用计数自动管理生命周期 |

### 3.6 统一算子契约接口 — IOperator

**完整源码**：

```cpp
// source/mimgs/common/Common.hpp (第 89-107 行)

// 统一算子契约接口
class IOperator
{
public:
    virtual ~IOperator() = default;

    virtual std::string_view getName() const noexcept = 0;    // 算子名称（注册中心 key）
    virtual void execute(IContext &context, const OperatorParams &params) = 0;  // 执行入口

protected:
    // 安全参数下转型：将基类引用转为具体参数类型
    template <typename T>
    const T &CastParams(const OperatorParams &params) const
    {
        const auto *derived = dynamic_cast<const T *>(&params);
        if (!derived)
        {
            throw ProcessingException(std::string(getName()) + ": Parameter mismatch.");
        }
        return *derived;
    }
};
```

**逐行设计解读**：

| 代码 | 说明 |
|------|------|
| `virtual ~IOperator() = default` | 虚析构，确保通过基类指针 `delete` 时子类正确析构 |
| `getName()` 返回 `string_view` | 零拷贝返回算子名称（通常是字符串字面量），避免每次调用创建 `std::string` |
| `execute()` 纯虚函数 | 所有算子必须实现此方法，这是流水线调度时的统一调用入口 |
| `CastParams<T>()` 模板方法 | 使用 `dynamic_cast` 做运行时类型安全检查；转型失败立即抛出 `ProcessingException` |
| `protected` 访问级别 | 仅子类算子可以调用 `CastParams`，外部代码无法直接使用 |

**CastParams 的安全保障机制**：

```text
Pipeline 调度时:
  operator->execute(context, *step.params)
       │
       ▼
ScaleOperator::execute()
       │
       ├── CastParams<ScaleParams>(params)
       │      │
       │      ├── dynamic_cast<const ScaleParams*>(&params)
       │      │
       │      ├── 成功 → 返回 ScaleParams 引用 ✅
       │      │
       │      └── 失败 → 抛出 "scale: Parameter mismatch." ❌
       │
       └── 后续代码可以安全使用 ScaleParams 的所有字段
```

### 4.4 像素格式转换 — ConvertFormat

**完整源码**：

```cpp
// source/mimgs/common/Utils.cpp (第 17-50 行)

std::shared_ptr<ImageAsset> ConvertFormat(const ImageAsset &src, PixelFormat tarFormat)
{
    // ── Step 1: 空指针校验 ──
    if (!src.data)
        throw ProcessingException("ConvertFormat: Source data is null.");

    // ── Step 2: 同格式 → 直接深拷贝 ──
    if (src.format == tarFormat)
    {
        auto copy = std::make_shared<ImageAsset>(src.id + "_copy", src.width, src.height, src.format);
        size_t totalBytes = static_cast<size_t>(src.width) * src.height * GetChannelCount(src.format);
        std::memcpy(copy->data.get(), src.data.get(), totalBytes);
        return copy;
    }

    // ── Step 3: 跨格式 → OpenCV cvtColor ──
    cv::Mat srcMat(src.height, src.width, MapToCVType(src.format), src.data.get());
    cv::Mat dstMat;

    if (src.format == PixelFormat::RGB888 && tarFormat == PixelFormat::RGBA8888)
        cv::cvtColor(srcMat, dstMat, cv::COLOR_RGB2RGBA);     // 3通道 → 4通道
    else if(src.format == PixelFormat::RGBA8888 && tarFormat == PixelFormat::RGB888)
        cv::cvtColor(srcMat, dstMat, cv::COLOR_RGBA2RGB);     // 4通道 → 3通道
    else
        throw ProcessingException("ConvertFormat: Unsupported conversion path.");

    // ── Step 4: 将 OpenCV 输出拷贝到 ImageAsset ──
    auto dstAsset = std::make_shared<ImageAsset>(src.id + "_conv", src.width, src.height, tarFormat);
    size_t rowBytes = static_cast<size_t>(src.width) * GetChannelCount(tarFormat);

    if(dstMat.isContinuous())
        std::memcpy(dstAsset->data.get(), dstMat.data, rowBytes * src.height);
    else
        for(int r = 0; r < dstMat.rows;++r)
            std::memcpy(dstAsset->data.get() + r*rowBytes, dstMat.ptr(r), rowBytes);

    return dstAsset;
}
```

**完整执行流程**：

```text
ConvertFormat(src, tarFormat)
    │
    ├── src.data == nullptr?  ──→ 抛出异常
    │
    ├── src.format == tarFormat?  ──→ 直接 memcpy 深拷贝，返回副本
    │
    └── src.format != tarFormat?  ──→ 走 OpenCV 转换路径
            │
            ├── 包装为 cv::Mat（零拷贝，共享 src.data 指针）
            │
            ├── cv::cvtColor(srcMat, dstMat, 转换码)
            │     RGB888→RGBA8888: cv::COLOR_RGB2RGBA
            │     RGBA8888→RGB888: cv::COLOR_RGBA2RGB
            │
            └── 将 dstMat 拷贝到新的 ImageAsset
                  ├── isContinuous() == true  → 一次 memcpy
                  └── isContinuous() == false → 逐行 memcpy
```

**连续 vs 非连续内存处理图解**：

```text
连续内存 (isContinuous() == true):
┌──────────────────────────────────────┐
│ Row0 Row1 Row2 Row3 ... RowN-1      │  → 一次 memcpy 全量拷贝
└──────────────────────────────────────┘
  rowBytes × height = totalBytes

非连续内存 (isContinuous() == false，含 padding):
┌──────────────┬───────┐
│ Row0         │ pad   │
│ Row1         │ pad   │  → 逐行 memcpy，跳过 padding 区域
│ Row2         │ pad   │
│ ...          │ ...   │
│ RowN-1       │ pad   │
└──────────────┴───────┘
  每行拷贝 rowBytes 字节，共 height 行
```

## 五、LRU 缓存淘汰机制 (LRUImageCache)

> 文件：`source/mimgs/common/LRUImageCache.hpp` + `source/mimgs/common/LRUImageCache.cpp`  
> 职责：全局单例 LRU 缓存，自动缓存算子的中间计算结果，重复请求时直接命中缓存跳过计算。

### 5.1 数据结构设计

**完整源码 — 头文件**：

```cpp
// source/mimgs/common/LRUImageCache.hpp

#ifndef LRU_IMAGE_CACHE_HPP
#define LRU_IMAGE_CACHE_HPP

#include "common/Common.hpp"

#include <unordered_map>
#include <mutex>
#include <list>
#include <memory>

namespace ei::mimgs
{
    class LRUImageCache
    {
    public:
        static LRUImageCache &getInstance();   // Meyers 单例入口

        // [OPTIMIZED-FIX] 原 API 命名为 getCapacity / putCapacity / clearCapacity，
        //                 语义不清晰（Capacity 是“容量”而非“获取/写入”动作）
        //                 修正为更简洁直观的 get / put / clear
        void setCapacity(size_t capacity);                                  // 设置/调整最大容量
        std::shared_ptr<ImageAsset> get(const std::string &key);            // 查询缓存
        void put(const std::string &key, std::shared_ptr<ImageAsset> asset); // 写入缓存
        void clear();                                                       // 清空全部缓存

    private:
        LRUImageCache(size_t capacity) : _capacity(capacity) {}
        ~LRUImageCache() = default;

        // 禁止拷贝和赋值（单例不允许被复制）
        LRUImageCache(const LRUImageCache &) = delete;
        LRUImageCache &operator=(const LRUImageCache &) = delete;

        // 淘汰超出容量的最久未使用条目
        void evict()
        {
            while(_list.size() > _capacity)
            {
                auto last = _list.back();    // 取链表尾部（最久未使用）
                _map.erase(last.first);      // 从哈希表删除
                _list.pop_back();            // 从链表删除
            }
        }

    private:
        size_t _capacity;                   // 最大缓存条目数
        std::mutex _mutex;                  // 线程安全互斥锁

        // 双向链表：前端 = 最近使用，后端 = 最久未使用（淘汰候选）
        std::list<std::pair<std::string, std::shared_ptr<ImageAsset>>> _list;

        // 哈希表：key → 链表迭代器（O(1) 定位节点）
        std::unordered_map<std::string, decltype(_list.begin())> _map;
    };
}

#endif // LRU_IMAGE_CACHE_HPP
```

**双数据结构原理**：

```text
                 _list（双向链表）
    ┌──────────────────────────────────────────────┐
    │  [最近使用] → [次新] → ... → [次旧] → [最久未使用]  │
    │   front()                                   back()  │
    └──────────────────────────────────────────────┘
                          ▲
                          │ O(1) 定位
    ┌──────────────────────────────────────────────┐
    │  _map: key → list::iterator                   │
    │  "scale_img_a_300x300" → iterator → [链表节点] │
    │  "rotate_img_b_90.0"   → iterator → [链表节点] │
    └──────────────────────────────────────────────┘

    为什么需要两个数据结构？
    ├── 链表：维护访问顺序（MRU 在前，LRU 在后），支持 O(1) 的 splice 移动
    └── 哈希表：支持 O(1) 的 key 查找，避免遍历链表
```

### 5.2 Meyers 单例模式

```cpp
// source/mimgs/common/LRUImageCache.cpp (第 5-9 行)

{
    static LRUImageCache instance(15);  // 默认容量 15
    return instance;
}
```

**要点**：
- C++11 起，局部 `static` 变量的初始化是线程安全的（编译器保证只初始化一次）
- 默认容量为 **15** 条缓存条目

### 5.3 get 操作（缓存命中/未命中）

**完整源码**：

```cpp
// source/mimgs/common/LRUImageCache.cpp
// [OPTIMIZED-FIX] 原函数名为 getCapacity，修正为 get

std::shared_ptr<ImageAsset> LRUImageCache::get(const std::string &key)
{
    std::lock_guard<std::mutex> lock(_mutex);   // 加锁

    auto it = _map.find(key);                    // O(1) 哈希查找
    if (it == _map.end())
        return nullptr;                          // 未命中

    // 将命中节点移到链表头部（标记为"最近使用"）
    _list.splice(_list.begin(), _list, it->second);

    return it->second->second;                   // 返回 shared_ptr<ImageAsset>
}
```

**执行流程图**：

```text
get("scale_img_a_300x300")
    │
    ├── lock(_mutex)
    │
    ├── _map.find(key)
    │     │
    │     ├── 未找到 → return nullptr（缓存未命中）
    │     │
    │     └── 找到 → 获得 list iterator
    │              │
    │              ├── _list.splice(begin, _list, it->second)
    │              │     将该节点从当前位置"剪切"到链表头部
    │              │     时间复杂度 O(1)，无需分配/释放内存
    │              │
    │              └── return shared_ptr<ImageAsset>
    │
    └── ~lock_guard → 自动解锁
```

**splice 操作图解**：

```text
操作前:
_list: [A] → [B] → [C] → [D]    _map: "C" → iterator_to_C

get("C") 触发 splice:
_list: [C] → [A] → [B] → [D]    _map: "C" → iterator_to_C（迭代器不失效）

"C" 被提升到最前面，表示"刚刚被访问过"
```

### 5.4 put 操作（写入/更新）

**完整源码**：

```cpp
// source/mimgs/common/LRUImageCache.cpp
// [OPTIMIZED-FIX] 原函数名为 putCapacity，修正为 put

void LRUImageCache::put(const std::string &key, std::shared_ptr<ImageAsset> asset)
{
    if(!asset) return;   // 空资产直接返回

    std::lock_guard<std::mutex> lock(_mutex);
    auto it = _map.find(key);

    // ── 情况 A：key 已存在 → 更新值并提升到头部 ──
    if(it != _map.end())
    {
        it->second->second = asset;   // 更新链表节点中的 shared_ptr
        _list.splice(_list.begin(), _list, it->second);  // 提升到头部
        return;
    }

    // ── 情况 B：key 不存在 → 插入头部 ──
    _list.push_front({key, asset});    // 链表头部插入新节点
    _map[key] = _list.begin();         // 哈希表记录 key → 迭代器

    evict();   // 检查是否超容量，淘汰尾部
}
```

**两种情况对比**：

```text
情况 A — key 已存在（更新）:
  _list: [A] → [B] → [C]         put("B", newAsset)
  _map:  "A"→it, "B"→it, "C"→it
                              ↓
  _list: [B'] → [A] → [C]         B 的值被更新，位置提升到头部
  _map:  "A"→it, "B"→it, "C"→it   迭代器不变，无需更新 _map

情况 B — key 不存在（新增）:
  _list: [A] → [B] → [C]         put("D", asset)
  _map:  "A"→it, "B"→it, "C"→it
                              ↓
  _list: [D] → [A] → [B] → [C]   D 插入到头部
  _map:  "A"→it, "B"→it, "C"→it, "D"→it
                              ↓
  evict(): 如果 _list.size() > _capacity → 淘汰尾部 [C]
```

### 5.5 evict 淘汰策略

```cpp
// LRUImageCache.hpp 内联定义

void evict()
{
    while(_list.size() > _capacity)
    {
        auto last = _list.back();     // 取链表最后一个节点（最久未使用）
        _map.erase(last.first);       // 从哈希表中删除对应 key
        _list.pop_back();             // 从链表中删除节点
    }
}
```

**淘汰图解**（假设 capacity = 3）：

```text
插入 D 后（size = 4 > capacity = 3）:
_list: [D] → [A] → [B] → [C]
                              ↑ back() = "C"，最久未使用

evict() 淘汰 C:
  _map.erase("C")
  _list.pop_back()

结果:
_list: [D] → [A] → [B]
_map:  "D"→it, "A"→it, "B"→it
```

### 5.6 setCapacity 动态调整

```cpp
// source/mimgs/common/LRUImageCache.cpp (第 11-16 行)

{
    std::lock_guard<std::mutex> lock(_mutex);
    _capacity = capacity;   // 更新容量上限
    evict();                // 立即淘汰超出的条目
}
```

**场景**：如果当前缓存了 15 条数据，用户调用 `setCapacity(5)`，则立即淘汰 10 条最久未使用的数据。

### 6.3 完整源码 — 实现文件

```cpp
// source/mimgs/pipeline/OperatorRegistry.cpp

#include "OperatorRegistry.hpp"
#include <mutex>

namespace ei::mimgs
{
    // ── Meyers 单例 ──
    OperatorRegistry &OperatorRegistry::getInstance()
    {
        static OperatorRegistry instance;
        return instance;
    }

    // ── 注册算子（写操作） ──
    void OperatorRegistry::RegisterOperator(std::unique_ptr<IOperator> op)
    {
        if (!op)
            return;

        std::unique_lock<std::shared_mutex> lock(_mutex);   // 写锁（独占）
        _registry[std::string(op->getName())] = std::move(op);
    }

    // ── 查找算子（读操作） ──
    IOperator *OperatorRegistry::getOperator(std::string_view name) const
    {
        // [OPTIMIZED-FIX] 原文使用 unique_lock（写锁/独占锁），导致多线程读操作串行化
        //                 修正为 shared_lock（读锁/共享锁），允许多个读操作并发
        std::shared_lock<std::shared_mutex> lock(_mutex);   // 读锁（共享）

        auto it = _registry.find(std::string(name));
        if(it != _registry.end())
            return it->second.get();    // 返回裸指针（不转移所有权）

        return nullptr;
    }
}
```

### 7.2 完整源码

```cpp
// source/mimgs/pipeline/Pipeline.hpp

#ifndef PIPELINE_HPP
#define PIPELINE_HPP
#include "common/Common.hpp"
#include <memory>
#include <vector>

namespace ei::mimgs
{
    // 流水线步骤定义（内部使用）
    struct PipelineStep
    {
        std::string opName;                    // 算子名称（用于查找注册中心）
        std::unique_ptr<OperatorParams> params; // 该步骤的参数（多态持有）
    };

    class Pipeline
    {
    public:
        Pipeline() = default;
        ~Pipeline() = default;

        // 禁止拷贝（流水线持有 unique_ptr 参数，不可简单复制）
        Pipeline(const Pipeline &) = delete;
        Pipeline &operator=(const Pipeline &) = delete;

        // 执行流水线：依次调度 params.steps 中的每个算子
        void Execute(IContext &context, const PipelineParams &params);
    };
}

#endif // PIPELINE_HPP
```

**PipelineStep vs PipelineParams.steps 的关系**：

```text
PipelineParams.steps (外部传入):
  vector<shared_ptr<OperatorParams>>
  ├── [0] shared_ptr<ScaleParams>     { opName 由外部约定 }
  ├── [1] shared_ptr<RotateParams>
  └── [2] shared_ptr<PuzzleParams>

PipelineStep (内部定义):
  struct { string opName; unique_ptr<OperatorParams> params; }

Pipeline::Execute 内部需要将 PipelineParams.steps 中的每个参数
按顺序交给对应的算子执行。算子名称可能需要从参数类型推断或从
外部 PipelineParams 中额外提供。
```

```cpp
// source/mimgs/process/ScaleOperator.cpp

#include "ScaleOperator.hpp"
#include "common/Utils.hpp"

#include <string>
#include <opencv2/opencv.hpp>

namespace ei::mimgs
{
    // ── 算子名称 ──
    std::string_view ScaleOperator::getName() const noexcept
    {
        return "scale";
    }

    // ── 参数校验 ──
    void ScaleParams::Validate() const
    {
        OperatorParams::Validate();  // 先校验基类（outputKey 非空）
        if (inputKey.empty())
            throw ProcessingException("Scale: inputKey empty.");
        // [OPTIMIZED-FIX] 原文为 tarWidth <= 0 || tarHeight <= 0
        //                 但 tarWidth / tarHeight 类型为 size_t（无符号），
        //                 与 0 比较 <= 永远为 false（编译器会报 -Wtautological-compare 警告）
        //                 修正为 == 0 检查
        if (tarWidth == 0 || tarHeight == 0)
            throw ProcessingException("Scale: invalid size.");
    }

    // ── 缓存签名 ──
    std::string ScaleParams::GetCacheSignature() const
    {
        return "scale_" + inputKey + "_" + std::to_string(tarWidth) + "x" + std::to_string(tarHeight);
        // 示例: "scale_img_a_300x300"
    }

    // ── 核心执行逻辑 ──
    void ScaleOperator::execute(IContext &context, const OperatorParams &params)
    {
        // Step 1: 安全下转型 + 参数校验
        const auto &scaleParams = CastParams<ScaleParams>(params);
        scaleParams.Validate();

        // Step 2: 从 Context 读取源图像
        auto srcAsset = context.getAsset(scaleParams.inputKey);
        if (!srcAsset)
            throw ProcessingException("Scale:Source asset '" + scaleParams.inputKey + "' not found in context");

        if (!srcAsset->data)
            throw ProcessingException("Scale: Source asset data is null");

        // Step 3: 将裸像素包装为 OpenCV Mat（零拷贝，共享内存）
        int cvType = MapToCVType(srcAsset->format);
        cv::Mat srcMat(srcAsset->height, srcAsset->width, cvType, srcAsset->data.get());

        // Step 4: 执行缩放（双线性插值 INTER_LINEAR）
        cv::Mat dstMat;
        cv::Size tarSize(static_cast<int>(scaleParams.tarWidth), static_cast<int>(scaleParams.tarHeight));
        cv::resize(srcMat, dstMat, tarSize, 0, 0, cv::INTER_LINEAR);

        // Step 5: 创建输出资产，拷贝像素数据
        auto dstAsset = std::make_shared<ImageAsset>(
            scaleParams.outputKey,
            scaleParams.tarWidth,
            scaleParams.tarHeight,
            srcAsset->format    // 保持与源图像相同的像素格式
        );
        size_t rowBytes = static_cast<size_t>(scaleParams.tarWidth) * GetChannelCount(srcAsset->format);

        // Step 6: 处理连续/非连续内存拷贝
        if (dstMat.isContinuous())
            std::memcpy(dstAsset->data.get(), dstMat.data, rowBytes * scaleParams.tarHeight);
        else
        {
            for(int r = 0; r < dstMat.rows; ++r)
            {
                std::memcpy(dstAsset->data.get() + r * rowBytes, dstMat.ptr(r), rowBytes);
            }
        }

        // Step 7: 将结果写入 Context
        context.setAsset(std::move(dstAsset));
    }
}
```

**OpenCV Mat 零拷贝包装原理**：


```cpp
// source/mimgs/process/RotateOperator.cpp

#include "RotateOperator.hpp"
#include "common/Utils.hpp"

#include <string>
#include <opencv2/opencv.hpp>

namespace ei::mimgs
{
    // ── 参数校验 ──
    void RotateParams::Validate() const
    {
        OperatorParams::Validate();
        if (inputKey.empty())
            // [OPTIMIZED-FIX] 原文误写为 "Scale: inputKey empty."，修正为正确的算子前缀
            throw ProcessingException("Rotate: inputKey empty.");
    }

    // ── 缓存签名 ──
    std::string RotateParams::GetCacheSignature() const
    {
        return "rotate_" + inputKey + "_" + std::to_string(angle);
        // 示例: "rotate_img_b_90.000000"
    }

    // ── 算子名称 ──
    std::string_view RotateOperator::getName() const noexcept
    {
        return "rotate";
    }

    // ── 核心执行逻辑 ──
    void RotateOperator::execute(IContext &context, const OperatorParams &params)
    {
        // Step 1: 安全下转型 + 参数校验
        const auto &rotateParams = CastParams<RotateParams>(params);
        rotateParams.Validate();

        // Step 2: 从 Context 读取源图像
        auto srcAsset = context.getAsset(rotateParams.inputKey);
        if (!srcAsset)
            // [OPTIMIZED-FIX] 原文误写为 "Scale:Source asset..."，修正为正确的算子前缀
            throw ProcessingException("Rotate: Source asset '" + rotateParams.inputKey + "' not found in context");

        if (!srcAsset->data)
            // [OPTIMIZED-FIX] 原文误写为 "Scale: Source asset..."，修正为正确的算子前缀
            throw ProcessingException("Rotate: Source asset data is null");

        // Step 3: 包装为 OpenCV Mat（零拷贝）
        int cvType = MapToCVType(srcAsset->format);
        cv::Mat srcMat(srcAsset->height, srcAsset->width, cvType, srcAsset->data.get());

        // Step 4: 计算旋转中心点
        cv::Point2f center(srcMat.cols / 2.0f, srcMat.rows / 2.0f);

        // Step 5: 生成 2x3 仿射变换矩阵
        cv::Mat rot = cv::getRotationMatrix2D(center, rotateParams.angle, 1.0);
        //                                           ^^^^^^^^^^^^^^^^^^  ^^^^
        //                                           旋转角度(度)        缩放因子(1.0=不缩放)

        // Step 6: 计算旋转后的包围盒（Bounding Box），防止图像被裁切
        cv::Size2f srcSize(static_cast<float>(srcMat.cols), static_cast<float>(srcMat.rows));
        cv::Rect2f bbox = cv::RotatedRect(cv::Point2f(), srcSize, rotateParams.angle).boundingRect2f();

        // Step 7: 确定目标画布尺寸
        cv::Size tarSize(
            static_cast<int>(std::round(bbox.width)),
            static_cast<int>(std::round(bbox.height))
        );

        // Step 8: 修正仿射矩阵的平移分量，使旋转后图像居中于目标画布
        rot.at<double>(0, 2) += tarSize.width / 2.0 - center.x;
        rot.at<double>(1, 2) += tarSize.height / 2.0 - center.y;

        // Step 9: 执行仿射变换
        cv::Mat dstMat;
        cv::warpAffine(
            srcMat, dstMat, rot, tarSize,
            cv::INTER_LINEAR,          // 双线性插值
            cv::BORDER_CONSTANT,       // 边界填充为常量
            cv::Scalar(0, 0, 0, 0)     // 填充透明黑色 (RGBA)
        );

        // Step 10: 创建输出资产并拷贝像素
        auto dstAsset = std::make_shared<ImageAsset>(
            rotateParams.outputKey,
            static_cast<uint32_t>(tarSize.width),
            static_cast<uint32_t>(tarSize.height),
            srcAsset->format
        );
        size_t rowBytes = static_cast<size_t>(tarSize.width) * GetChannelCount(dstAsset->format);

        if(dstMat.isContinuous())
        {
            std::memcpy(dstAsset->data.get(), dstMat.data, rowBytes * tarSize.height);
        }
        else
        {
            for(int r = 0; r < dstMat.rows; ++r)
            {
                std::memcpy(dstAsset->data.get() + r * rowBytes, dstMat.ptr(r), rowBytes);
            }
        }

        // Step 11: 写入 Context
        context.setAsset(std::move(dstAsset));
    }
}
```

**旋转算法核心数学原理**：

```text
1. 仿射变换矩阵 (2x3):
   ┌                          ┐
   │ cos(θ)  -sin(θ)  tx     │
   │ sin(θ)   cos(θ)  ty     │
   └                          ┘
   其中 (tx, ty) 是平移分量

2. getRotationMatrix2D(center, angle, scale) 生成以 center 为中心的旋转矩阵

3. 问题：旋转后图像可能超出原始画布范围
   ┌──────────┐
   │  原始图像 │     旋转 θ 后
   └──────────┘     ╱─────────╲
                   │  旋转图像  │  ← 部分像素超出原始范围
                    ╲─────────╱

4. 解决方案：计算旋转后包围盒 (Bounding Box)
   cv::RotatedRect(center, srcSize, angle).boundingRect2f()
   → 返回能完整包含旋转后图像的最小正矩形

5. 修正平移分量:
   rot(0,2) += tarWidth/2 - centerX
   rot(1,2) += tarHeight/2 - centerY
   → 确保旋转后图像居中于新的目标画布

6. warpAffine 在新画布上执行变换，边界填充为透明黑色
```

**旋转包围盒示意**：

```text
原始 (800x600):                旋转 45° 后包围盒 (~990x990):
┌────────────┐                 ┌───────────────────┐
│            │    rotate 45°   │     ╱────────╲    │
│   800x600  │   ──────────→   │    │ 旋转图像 │   │
│            │                 │     ╲────────╱    │
└────────────┘                 └───────────────────┘
                                990x990 (完整包含)
```

#### 完整源码 — 实现文件

```cpp
// source/mimgs/process/PuzzleOperator.cpp

#include "PuzzleOperator.hpp"
#include "common/Utils.hpp"

#include <opencv2/opencv.hpp>

namespace ei::mimgs
{
    // ── 参数校验 ──
    void PuzzleParams::Validate() const
    {
        OperatorParams::Validate();
        if (inputKeys.empty())
            // [OPTIMIZED-FIX] 原文误写为 "Scale: inputKey empty."，修正为正确的算子前缀
            throw ProcessingException("Puzzle: inputKeys empty.");
        // [OPTIMIZED-FIX] 原文 padding <= 0 校验过于严格：
        //                 uint32_t 不可能为负，且 padding=0 表示无间距是合法场景
        //                 修正为仅校验核心尺寸参数
        if (rows == 0 || cols == 0 || cellWidth == 0 || cellHeight == 0)
            // [OPTIMIZED-FIX] 原文误写为 "Scale: invalid size."，修正为正确的算子前缀
            throw ProcessingException("Puzzle: invalid grid size.");
    }

    // ── 缓存签名（使用哈希压缩） ──
    std::string PuzzleParams::GetCacheSignature() const
    {
        // 1. 在栈上拼接原始字符串（仅作为哈希源）
        std::string raw;
        for (const auto &key : inputKeys)
            raw += key + ",";
        raw += std::to_string(rows) + "_" + std::to_string(cols) + "_"
             + std::to_string(cellWidth) + "_" + std::to_string(cellHeight) + "_"
             + std::to_string(padding) + "_"
             + std::to_string(bgColor[0]) + "_" + std::to_string(bgColor[1]) + "_"
             + std::to_string(bgColor[2]) + "_" + std::to_string(bgColor[3]);

        // 2. 使用 std::hash 压缩为 size_t (64位整数)
        size_t hashVal = std::hash<std::string>{}(raw);

        // 3. 转化为固定长度的 16 进制字符串 (形如 "pz_f3a7c21e")
        char buf[32];
        std::snprintf(buf, sizeof(buf), "pz_%zx", hashVal);
        return std::string(buf);
    }

    // ── 算子名称 ──
    std::string_view PuzzleOperator::getName() const noexcept
    {
        return "puzzle";
    }

    // ── 核心执行逻辑 ──
    void PuzzleOperator::execute(IContext &context, const OperatorParams &params)
    {
        const auto &puzzleParams = CastParams<PuzzleParams>(params);
        puzzleParams.Validate();

        // ── Step 1: 计算画布总尺寸 ──
        uint32_t totalWidth = puzzleParams.cols * puzzleParams.cellWidth
            + (puzzleParams.cols > 1 ? (puzzleParams.cols - 1) * puzzleParams.padding : 0);
        uint32_t totalHeight = puzzleParams.rows * puzzleParams.cellHeight
            + (puzzleParams.rows > 1 ? (puzzleParams.rows - 1) * puzzleParams.padding : 0);

        // ── Step 2: 确定输出格式（统一为 RGBA8888） ──
        PixelFormat outputFormat = PixelFormat::RGBA8888;
        int outputCVType = MapToCVType(outputFormat);
        int outputChannels = GetChannelCount(outputFormat);

        // ── Step 3: 创建画布并填充背景色 ──
        cv::Mat dstMat(static_cast<int>(totalHeight), static_cast<int>(totalWidth), outputCVType);
        // [OPTIMIZED-FIX] 原注释通道映射描述混乱，修正为清晰的说明：
        //   bgColor 数组布局为 [B, G, R, A]
        //   OpenCV 的 cv::Scalar 对 4 通道图像的内部顺序为 [B, G, R, A]
        //   因此直接按顺序映射即可
        cv::Scalar cvBgColor(
            puzzleParams.bgColor[0],  // bgColor[0]=B  → cv::Scalar 第 1 位 (B)
            puzzleParams.bgColor[1],  // bgColor[1]=G  → cv::Scalar 第 2 位 (G)
            puzzleParams.bgColor[2],  // bgColor[2]=R  → cv::Scalar 第 3 位 (R)
            puzzleParams.bgColor[3]   // bgColor[3]=A  → cv::Scalar 第 4 位 (A)
        );
        dstMat.setTo(cvBgColor);

        // ── Step 4: 遍历网格，逐个放置子图 ──
        size_t currentInputIndex = 0;
        for (uint32_t r = 0; r < puzzleParams.rows; ++r)
        {
            for (uint32_t c = 0; c < puzzleParams.cols; ++c)
            {
                if (currentInputIndex >= puzzleParams.inputKeys.size())
                    break;

                const std::string &inputKey = puzzleParams.inputKeys[currentInputIndex];
                auto srcAsset = context.getAsset(inputKey);

                // 如果资产不存在或数据为空，跳过该单元格
                if (!srcAsset || !srcAsset->data)
                {
                    currentInputIndex++;
                    continue;
                }

                // 包装为 OpenCV Mat
                cv::Mat currentSrcMat(
                    srcAsset->height, srcAsset->width,
                    MapToCVType(srcAsset->format), srcAsset->data.get()
                );

                // 格式统一：如果源是 RGB888 而输出需要 RGBA8888，先转换
                if (srcAsset->format == PixelFormat::RGB888 && outputFormat == PixelFormat::RGBA8888)
                {
                    cv::Mat tempConvertedMat;
                    cv::cvtColor(currentSrcMat, tempConvertedMat, cv::COLOR_RGB2RGBA);
                    currentSrcMat = tempConvertedMat;
                }

                // 缩放子图到单元格尺寸
                cv::Mat resizedSrcMat;
                cv::resize(
                    currentSrcMat, resizedSrcMat,
                    cv::Size(static_cast<int>(puzzleParams.cellWidth),
                             static_cast<int>(puzzleParams.cellHeight)),
                    0, 0, cv::INTER_LINEAR
                );

                // 计算放置偏移量
                int xOffset = static_cast<int>(c * (puzzleParams.cellWidth + puzzleParams.padding));
                int yOffset = static_cast<int>(r * (puzzleParams.cellHeight + puzzleParams.padding));

                // ROI (Region of Interest) 拷贝到画布
                cv::Rect roi(xOffset, yOffset, resizedSrcMat.cols, resizedSrcMat.rows);
                resizedSrcMat.copyTo(dstMat(roi));

                currentInputIndex++;
            }

            if (currentInputIndex >= puzzleParams.inputKeys.size())
                break;
        }

        // ── Step 5: 创建输出资产并拷贝像素 ──
        auto dstAsset = std::make_shared<ImageAsset>(
            puzzleParams.outputKey, totalWidth, totalHeight, outputFormat
        );

        size_t totalBytes = static_cast<size_t>(totalWidth) * totalHeight * outputChannels;
        if (dstMat.isContinuous())
            std::memcpy(dstAsset->data.get(), dstMat.data, totalBytes);
        else
        {
            size_t rowBytes = static_cast<size_t>(totalWidth) * outputChannels;
            for (int r = 0; r < dstMat.rows; ++r)
            {
                std::memcpy(dstAsset->data.get() + r * rowBytes, dstMat.ptr(r), rowBytes);
            }
        }

        // ── Step 6: 写入 Context ──
        context.setAsset(std::move(dstAsset));
    }
}
```

**拼图布局计算图解**：

```text
以 rows=2, cols=3, cellWidth=200, cellHeight=150, padding=10 为例:

totalWidth  = 3 × 200 + (3-1) × 10 = 620
totalHeight = 2 × 150 + (2-1) × 10 = 310

画布布局 (620 × 310):
┌──────────┬──┬──────────┬──┬──────────┐
│          │  │          │  │          │
│ Cell(0,0)│10│ Cell(0,1)│10│ Cell(0,2)│
│ 200×150  │  │ 200×150  │  │ 200×150  │
│          │  │          │  │          │
├──────────┼──┼──────────┼──┼──────────┤
│    10    │10│    10    │10│    10    │
├──────────┼──┼──────────┼──┼──────────┤
│          │  │          │  │          │
│ Cell(1,0)│10│ Cell(1,1)│10│ Cell(1,2)│
│ 200×150  │  │ 200×150  │  │ 200×150  │
│          │  │          │  │          │
└──────────┴──┴──────────┴──┴──────────┘

Cell(r,c) 的左上角坐标:
  xOffset = c × (cellWidth + padding)
  yOffset = r × (cellHeight + padding)

例如 Cell(1,2):
  xOffset = 2 × (200 + 10) = 420
  yOffset = 1 × (150 + 10) = 160
```

**ROI 拷贝原理**：

```cpp

resizedSrcMat.copyTo(dstMat(roi));
//                  ^^^^^^^^^^^
//                  dstMat(roi) 返回一个 Mat "视图"（不拷贝数据）
//                  copyTo 将源矩阵的像素写入这个视图区域
```

## 九、门面层 (Facade) — SDK 对外接口

### 9.1 纯虚接口 — IImages

**完整源码**：

```cpp
// include/mimgs/interfaces/IImages.hpp

#ifndef I_IMAGES_HPP
#define I_IMAGES_HPP

#include <memory>
#include <unordered_map>
#include <string>

namespace ei::mimgs
{
    struct ImageAsset;       // 前置声明（不暴露完整定义）
    struct PipelineParams;   // 前置声明

    class IImages
    {
    public:
        virtual ~IImages() = default;

        virtual bool execute(
            const PipelineParams& params,
            const std::unordered_map<std::string, std::shared_ptr<ImageAsset>>& inputs,
            std::unordered_map<std::string, std::shared_ptr<ImageAsset>>& outputs
        ) = 0;

        virtual void clearCache() = 0;
        virtual void setCacheCapacity(size_t capacity) = 0;
    };
}

#endif // I_IMAGES_HPP
```

**接口设计解读**：

| 方法 | 说明 |
|------|------|
| `execute()` | 执行图像处理流水线。`inputs` 传入原始图像，`outputs` 返回处理结果，返回 `bool` 表示成功/失败 |
| `clearCache()` | 清空全局 LRU 缓存 |
| `setCacheCapacity()` | 动态调整 LRU 缓存的最大条目数 |

**为什么用纯虚接口？**

```text
1. ABI 稳定性：
   纯虚接口不包含任何数据成员，其内存布局永远是一个 vptr 指针。
   即使后续在实现类中添加更多成员变量，IImages 的二进制布局不变，
   已编译的外部客户端无需重新编译。

2. 依赖倒置：
   外部代码依赖 IImages 接口（抽象），而非 Images 具体类。
   可以在不修改客户端的情况下替换实现（如 Mock 测试）。

3. 前置声明隔离：
   ImageAsset 和 PipelineParams 在接口头文件中仅为前置声明，
   客户端编译时无需包含它们的完整定义，缩短编译时间。
```

### 9.4 门面类 — Images（Pimpl 模式）

**完整源码**：

```cpp
// include/mimgs/Mimgs.hpp (第 32-45 行)

class MIMGS_API Images : public IImages
{
public:
    Images() = default;
    ~Images() override;  // 必须在 .cpp 中定义，否则 unique_ptr<Impl> 遇到不完整类型报错

    bool execute(const PipelineParams &params,
                 const std::unordered_map<std::string, std::shared_ptr<ImageAsset>> &inputs,
                 std::unordered_map<std::string, std::shared_ptr<ImageAsset>> &outputs) override;
    void clearCache() override;
    void setCacheCapacity(size_t capacity) override;

private:
    class Impl;                      // 前置声明（编译防火墙）
    std::unique_ptr<Impl> _impl;    // 唯一的成员变量
};
```

**Pimpl 模式完整原理**：

```text
外部头文件 Mimgs.hpp:                    内部实现 Mimgs.cpp:
┌─────────────────────────┐             ┌─────────────────────────────────┐
│ class Images {          │             │ class Images::Impl {            │
│   class Impl;    ←──────┼──前置声明───┼──   Pipeline pipeline;          │
│   unique_ptr<Impl> _impl│             │   // ... 其他内部成员 ...        │
│ };                      │             │ };                              │
└─────────────────────────┘             └─────────────────────────────────┘

为什么 ~Images() 必须在 .cpp 中定义？
  因为 unique_ptr<Impl> 析构时需要看到 Impl 的完整定义（才能调用 Impl 的析构函数）。
  如果析构函数在头文件中 default，编译器会报错：
    "invalid application of 'sizeof' to incomplete type 'Images::Impl'"
```

## 十一、线程安全模型

| 组件 | 并发策略 | 说明 |
|------|---------|------|
| `IContext` | **请求隔离**（栈上局部变量） | 每次 `execute()` 创建独立实例，不同线程无共享状态，天然线程安全 |
| `OperatorRegistry` | `std::shared_mutex` 读写锁 | 注册时 `unique_lock`（写独占），查找时也使用 `unique_lock`（应改为 `shared_lock`） |
| `LRUImageCache` | `std::mutex` 互斥锁 | 全局单例，所有操作（get/put/set/clear）加锁 |
| `IOperator` 实例 | **无状态（Stateless）** | 算子本身不持有可变成员变量，可安全并发调用 |
| `Images::Impl` | 委托给上述组件 | 自身无额外共享状态 |

**线程安全全景图**：

```text
Thread 1                              Thread 2
────────                              ────────
Images::execute()                     Images::execute()
    │                                      │
    ├── IContext ctx1;  (栈上)              ├── IContext ctx2;  (栈上)
    │   (独立，无竞争)                      │   (独立，无竞争)
    │                                      │
    ├── Registry::get("scale")             ├── Registry::get("rotate")
    │   (shared_mutex 保护)                │   (shared_mutex 保护)
    │                                      │
    ├── scale_op->execute(ctx1, p1)        ├── rotate_op->execute(ctx2, p2)
    │   (操作 ctx1，无竞争)                │   (操作 ctx2，无竞争)
    │                                      │
    ├── LRU::put(sig1, result1)            ├── LRU::put(sig2, result2)
    │   (mutex 保护，串行写入)              │   (mutex 保护，串行写入)
```

### Step 2: 创建实现文件

```cpp
// source/mimgs/process/CropOperator.cpp

#include "CropOperator.hpp"
#include "common/Utils.hpp"
#include <opencv2/opencv.hpp>

namespace ei::mimgs
{
    std::string_view CropOperator::getName() const noexcept { return "crop"; }

    void CropParams::Validate() const
    {
        OperatorParams::Validate();
        if (inputKey.empty())
            throw ProcessingException("Crop: inputKey empty.");
        if (cropWidth == 0 || cropHeight == 0)
            throw ProcessingException("Crop: invalid crop size.");
    }

    std::string CropParams::GetCacheSignature() const
    {
        return "crop_" + inputKey + "_"
             + std::to_string(offsetX) + "_" + std::to_string(offsetY) + "_"
             + std::to_string(cropWidth) + "x" + std::to_string(cropHeight);
    }

    void CropOperator::execute(IContext &context, const OperatorParams &params)
    {
        const auto &cropParams = CastParams<CropParams>(params);
        cropParams.Validate();

        auto srcAsset = context.getAsset(cropParams.inputKey);
        if (!srcAsset || !srcAsset->data)
            throw ProcessingException("Crop: Source asset not found or data is null.");

        cv::Mat srcMat(srcAsset->height, srcAsset->width,
                       MapToCVType(srcAsset->format), srcAsset->data.get());

        cv::Rect cropRect(cropParams.offsetX, cropParams.offsetY,
                          cropParams.cropWidth, cropParams.cropHeight);
        cropRect &= cv::Rect(0, 0, srcMat.cols, srcMat.rows);  // 边界安全裁剪

        cv::Mat croppedMat = srcMat(cropRect).clone();

        auto dstAsset = std::make_shared<ImageAsset>(
            cropParams.outputKey,
            static_cast<uint32_t>(croppedMat.cols),
            static_cast<uint32_t>(croppedMat.rows),
            srcAsset->format);

        size_t rowBytes = static_cast<size_t>(croppedMat.cols) * GetChannelCount(srcAsset->format);
        if (croppedMat.isContinuous())
            std::memcpy(dstAsset->data.get(), croppedMat.data, rowBytes * croppedMat.rows);
        else
            for (int r = 0; r < croppedMat.rows; ++r)
                std::memcpy(dstAsset->data.get() + r * rowBytes, croppedMat.ptr(r), rowBytes);

        context.setAsset(std::move(dstAsset));
    }
}
```
